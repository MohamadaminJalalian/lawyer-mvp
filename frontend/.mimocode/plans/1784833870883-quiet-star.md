# Plan: Authentication, Session Management & Access Control Module

## Context

Implement the auth module for a law office management system ("سامانه مدیریت پرونده دفتر وکالت") using Next.js 16.2.11 (App Router) + TypeScript + Tailwind CSS 4. The project is a fresh boilerplate with root-level `app/` — we will reorganize into `src/` per the CLAUDE.md spec. The UI must be **RTL Persian** with a modern, professional legal/administrative aesthetic.

**Critical Next.js 16 breaking change**: `middleware.ts` is deprecated. The correct convention is `proxy.ts` with a named export `proxy()` (not `middleware()`).

## Phase 2: Mock API Route Handlers

Create Next.js Route Handlers under `src/app/api/auth/` that return mock data matching the CLAUDE.md API spec.

### 2.1 Mock Users Data (`src/lib/mock-users.ts`)
Two users:
- `{ id: "u-admin-001", fullName: "علی رضایی", username: "admin", password: "123456", role: "ADMIN" }`
- `{ id: "u-staff-001", fullName: "مریم احمدی", username: "staff", password: "123456", role: "STAFF" }`

### 2.2 `POST /api/auth/login` (`src/app/api/auth/login/route.ts`)
- Parse JSON body, validate username/password
- Return 401 with `{ error: "نام کاربری یا رمز عبور صحیح نیست." }` for invalid credentials
- Return 403 with `{ error: "حساب کاربری شما غیرفعال است..." }` for inactive (not implemented in MVP, but structure for future)
- On success: set `Set-Cookie` header for session token (HttpOnly, Secure, SameSite=Lax), return `{ accessToken, expiresIn: 3600, user }`
- **Note**: Since we're using mock data, the "token" will be a simple signed string. In production, the backend would handle JWT signing.

### 2.3 `POST /api/auth/logout` (`src/app/api/auth/logout/route.ts`)
- Delete the session cookie
- Return `{ success: true }`

### 2.4 `GET /api/auth/me` (`src/app/api/auth/me/route.ts`)
- Read session cookie
- If no session → return 401
- If valid session → return user data (without password)
- Return 401 with `{ error: "نشست نامعتبر" }` for invalid/missing session

## Phase 3: API Client & Error Handling

### 3.1 `src/lib/api-client.ts`
- Centralized `apiClient` function wrapping `fetch`
- Always includes `credentials: "include"` (for HttpOnly cookies)
- Handles response status codes:
  - 200: parse JSON and return
  - 400: throw with validation error message
  - 401: trigger session cleanup + redirect to `/auth/login` (import AuthProvider cleanup)
  - 403: throw with "عدم دسترسی" message
  - 404: throw with "یافت نشد" message
  - 500: throw with generic server error message
  - Network error: throw with "ارتباط با سرور برقرار نشد" message
- Export `get`, `post` helper functions

### 3.2 `src/lib/api-error-handler.ts`
- Error classes/types for different API error scenarios
- `handleApiError(response: Response): Promise<never>` — parses error body and throws appropriate error
- Centralized error message mapping ( Persian messages per CLAUDE.md spec)

**Files created**: `src/lib/api-client.ts`, `src/lib/api-error-handler.ts`

## Phase 5: AuthProvider & useAuth Hook

### 5.1 `src/features/auth/providers/AuthProvider.tsx`
- `'use client'` component
- React Context providing: `user`, `loading`, `authenticated`, `error`, `login()`, `logout()`, `hasRole()`
- On mount: call `getMe()` to check existing session
  - Success → set user, authenticated=true
  - 401 → set unauthenticated
  - Network error → set error state
- `login()`: call auth API, store user in state, redirect
- `logout()`: call auth API (catch errors), clear state, redirect to `/auth/login`
  - **Critical**: Even if logout API fails, clear local state and redirect
- `hasRole(role)`: check user.role === role
- Expose `isAuthenticated` computed from state

### 5.2 `src/features/auth/hooks/useAuth.ts`
- Simple hook: `useContext(AuthContext)`
- Returns typed context value
- Throws error if used outside AuthProvider

**Files created**: `src/features/auth/providers/AuthProvider.tsx`, `src/features/auth/hooks/useAuth.ts`

## Phase 8: Proxy (Route Guard)

### 8.1 `proxy.ts` (project root)
- **Next.js 16**: file is `proxy.ts` (NOT `middleware.ts`), export is `proxy()` (NOT `middleware()`)
- Protected routes: `/`, `/clients`, `/cases`
- Public routes: `/auth/login`, `/api/*`
- Logic:
  1. Check if route is protected
  2. If protected: check session cookie exists (optimistic check only — no DB call in proxy)
  3. If no session → redirect to `/auth/login?redirect=<current_path>`
  4. If on public route with session → redirect to `/` (dashboard)
- Matcher: exclude `/_next/*`, `/api/*`, static files

**File created**: `proxy.ts`

3. **Login flow**: Navigate to `/auth/login`, submit credentials, verify redirect to dashboard
4. **Session persistence**: Refresh page, verify session is maintained
5. **Logout flow**: Click logout, confirm modal, verify redirect to login page
6. **Route protection**: Try accessing `/` without session, verify redirect to login
7. **Redirect after login**: Access a protected page → redirected to login → login → redirected back to original page
8. **401 handling**: Simulate expired session, verify cleanup + redirect
9. **Role-based UI**: Login as STAFF, verify "بایگانی پرونده" button is hidden. Login as ADMIN, verify it's visible.
10. **Responsive design**: Test at mobile (375px), tablet (768px), desktop (1024px+)
11. **RTL**: Verify all text is right-to-left, form fields are properly aligned
12. **Error messages**: Test all error states from CLAUDE.md spec
13. **Password security**: Verify password never appears in URL, console, or localStorage

## Key Design Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Session storage | HttpOnly Cookie (mock) | Per CLAUDE.md spec; mock handlers set cookies |
| Route protection | `proxy.ts` (Next.js 16) | Correct convention for Next.js 16; middleware is deprecated |
| State management | React Context (AuthProvider) | Per CLAUDE.md spec |
| Styling | Tailwind CSS 4 | Already installed; modern, efficient |
| Font | Vazirmatn (Google Fonts) | Best Persian/Arabic web font for professional UI |
| Primary color | Deep navy (#1e3a5f) | Trust, professionalism — appropriate for legal software |
| Mock data | Next.js Route Handlers | More realistic, supports cookies, closer to real backend |
| Project structure | `src/` directory | Per CLAUDE.md spec, cleaner separation |
