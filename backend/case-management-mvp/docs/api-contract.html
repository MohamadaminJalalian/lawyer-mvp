۱. قوانین عمومی ارتباط با API

تمام درخواست‌ها و پاسخ‌ها باید با فرمت JSON باشند. بنابراین در درخواست‌هایی که Body دارند، Header زیر ارسال شود: 

{
  "Content-Type": "application/json"
}

تمام APIهای داخلی نیاز به احراز هویت دارند. فرانت‌اند باید توکن JWT را در Header زیر ارسال کند: 

{
  "Authorization": "Bearer ACCESS_TOKEN"
}
اگر توکن ارسال نشود یا معتبر نباشد، بک‌اند باید پاسخ 401 برگرداند.

Base URL

آدرس اصلی سرور بسته به محیط اجرا توسط تیم بک‌اند اعلام می‌شود. نمونه:

https://api.example.com

در این مستند Endpointها بدون Base URL نوشته شده‌اند. مثال:

GET /clients

۲. ساختار استاندارد پاسخ‌های لیستی

هر API که لیست برمی‌گرداند، مثل لیست موکلان یا لیست پرونده‌ها، باید ساختار صفحه‌بندی زیر را داشته باشد: 

{
  "items": [],
  "page": 1,
  "pageSize": 20,
  "totalCount": 0,
  "totalPages": 0
}
فیلد توضیح
items آرایه‌ای از رکوردهای برگشتی
page شماره صفحه فعلی
pageSize تعداد رکورد در هر صفحه
totalCount تعداد کل رکوردها
totalPages تعداد کل صفحات

۳. ساختار استاندارد خطاها

همه خطاها باید تا حد امکان با فرمت زیر برگردند: 

{
  "message": "پیام کلی خطا",
  "errors": {
    "fieldName": [
      "متن خطای مربوط به فیلد"
    ]
  }
}

اگر خطا مربوط به یک فیلد خاص نباشد، ممکن است فقط فیلد message برگردد.

کدهای خطای استاندارد

کد وضعیت کاربرد نمونه پیام
400 Bad Request اطلاعات ارسالی نامعتبر است اطلاعات واردشده معتبر نیست.
401 Unauthorized JWT ارسال نشده یا معتبر نیست نشست شما معتبر نیست.
403 Forbidden کاربر مجوز انجام عملیات را ندارد شما اجازه انجام این عملیات را ندارید.
404 Not Found رکورد موردنظر پیدا نشد رکورد موردنظر پیدا نشد.
409 Conflict داده تکراری است اطلاعات واردشده قبلاً ثبت شده است.
500 Internal Server Error خطای داخلی سرور خطای داخلی سرور رخ داده است.

نمونه خطای اعتبارسنجی 400

{
  "message": "اطلاعات واردشده معتبر نیست.",
  "errors": {
    "internalNumber": [
      "شماره داخلی پرونده الزامی است."
    ],
    "title": [
      "عنوان پرونده باید حداقل ۳ کاراکتر باشد."
    ]
  }
}

نمونه خطای تکراری بودن داده 409

{
  "message": "اطلاعات واردشده قبلاً ثبت شده است.",
  "errors": {
    "internalNumber": [
      "شماره داخلی پرونده قبلاً ثبت شده است."
    ]
  }
}

نمونه خطای عدم دسترسی 403

{
  "message": "شما اجازه انجام این عملیات را ندارید."
}

۴. نقش‌ها و دسترسی‌ها

نقش دسترسی‌ها
ADMIN مشاهده، ثبت، ویرایش و بایگانی پرونده
STAFF مشاهده، ثبت و ویرایش؛ بدون اجازه بایگانی پرونده
عملیات بایگانی پرونده فقط برای نقش ADMIN مجاز است. اگر STAFF درخواست بایگانی ارسال کند، پاسخ باید 403 باشد.

۵. APIهای موکلان

۵.۱. دریافت لیست موکلان

این API برای دریافت لیست موکلان همراه با Search و Pagination استفاده می‌شود.

قوانین اعتبارسنجی پرونده

فیلد قانون
internalNumber اجباری، حداکثر ۵۰ کاراکتر، یکتا، ورود دستی توسط کاربر
title اجباری، حداقل ۳ و حداکثر ۲۰۰ کاراکتر
clientId اجباری، باید به موکل موجود و فعال اشاره کند
categoryId اجباری، باید به دسته‌بندی موجود و فعال اشاره کند
courtCaseNumber اختیاری، حداکثر ۱۰۰ کاراکتر
courtName اختیاری، حداکثر ۲۰۰ کاراکتر
opponentName اختیاری، حداکثر ۱۵۰ کاراکتر
description اختیاری، حداکثر ۲۰۰۰ کاراکتر
مقدار internalNumber قبل از ذخیره باید Trim شود. در MVP فعلی مقدار شماره داخلی فقط می‌تواند شامل حروف، اعداد، خط تیره و اسلش باشد.
شماره داخلی پرونده توسط بک‌اند تولید نمی‌شود. فرانت‌اند باید آن را از کاربر دریافت کند.

Response 201

  "id": "case-uuid",
  "internalNumber": "1405-001",
  "title": "پرونده مطالبه وجه",
  "status": "ACTIVE",
  "createdAt": "2026-07-14T09:00:00Z"
}

Conflict 409 - شماره داخلی تکراری

{
  "message": "شماره داخلی واردشده قبلاً برای پرونده دیگری ثبت شده است.",
  "errors": {
    "internalNumber": [
      "این شماره داخلی تکراری است."

۷.۵. بایگانی پرونده

POST ADMIN ONLY

POST /cases/{id}/archive
این Endpoint فقط برای کاربر دارای نقش ADMIN مجاز است.

قوانین بایگانی

قانون توضیح
حذف فیزیکی ممنوع پرونده نباید از دیتابیس حذف شود
تغییر وضعیت وضعیت پرونده از ACTIVE به ARCHIVED تغییر می‌کند
ثبت زمان فیلد archivedAt باید با زمان UTC ثبت شود
ثبت کاربر شناسه کاربر بایگانی‌کننده باید در archivedByUserId ذخیره شود
عدم دسترسی STAFF اگر STAFF درخواست بدهد، پاسخ 403 برگردد

{
  "id": "case-uuid",
  "internalNumber": "1405-001",
  "status": "ARCHIVED",
  "archivedAt": "2026-07-14T10:00:00Z"
}

۸. وضعیت‌های پرونده

وضعیت پرونده فقط یکی از دو مقدار زیر است: 

[
  "ACTIVE",
  "ARCHIVED"
]
وضعیت معنی
ACTIVE پرونده فعال است و در جریان کاری معمول قرار دارد
ARCHIVED
